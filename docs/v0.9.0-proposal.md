# v0.9.0 theme proposal

Status: **draft** — owner picks one (or combines two) theme(s) for the next
minor release.

v0.8.x delivered the plumbing: provider abstraction, failover with retry +
error classification, append-only usage log, and a Usage settings tab. v0.9.0
should pay that off with something the operator actually sees day-to-day.

## Candidates

| # | Theme                          | Effort | Value | Risk | Notes |
|---|--------------------------------|--------|-------|------|-------|
| 1 | Session record/replay          | M      | High  | Low  | Capture `(asr_transcript, screenshot?, answer, provider, latency)` per question to disk; replay through `LLMEngine` for prompt tuning without a live mic. Foundations exist in `usage.jsonl`. |
| 2 | Prompt template editor (live)  | S      | Med   | Low  | Already have a Prompts tab; add A/B preview pane that runs the *current* prompt against a saved session from #1 and diffs the answer. Strongest if paired with #1. |
| 3 | Multi-language prompts         | S      | Med   | Med  | `prompts/{technical,behavioral,…}.{zh,en,ja}.md` + language switcher in Settings. Risk: prompt drift across locales without owner review. |
| 4 | Retry-chain stats dashboard    | S      | Med   | Low  | Extend the Usage tab with a "Failover" panel: win-rate per provider, mean retries per request, cost per provider over time. Pure read on `usage.jsonl`. |
| 5 | Cross-family vision failover   | L      | Low   | High | Translate a single vision request into per-provider payloads so the fallback chain works across openai↔gemini. Today blocked by payload-shape mismatch (see README caveat). Big payoff is small — most users pick one vision family and stick with it. |

## Recommendation

**#1 + #2 bundled** as the v0.9.0 theme.

Reasoning:

- #1 is the missing prerequisite for any prompt-engineering loop. Today, the
  only way to test a prompt change is to re-do an interview, which is
  expensive and non-deterministic.
- #2 is cheap once #1 lands and turns the Prompts tab from a text editor into
  a feedback tool. Without #1 it's just notepad.
- #4 is tempting (it's small) but the Usage tab already covers the 80% case.
  Worth a fast-follow point release (v0.9.1) rather than the headline theme.
- #3 should be punted to v0.10.x — the prompts haven't stabilized enough to
  justify maintaining N translations.
- #5 is not worth the engineering cost given the small fraction of users
  who'd actually run a cross-family chain.

## Tentative scope for v0.9.0

1. `src/session_recorder.py` — append-only JSONL at `~/.ghostpilot/sessions/`,
   one file per session (UTC timestamp). Records the canonical
   `SessionEvent(ts, q_type, transcript, screenshot_path?, answer, provider,
   total_ms)`.
2. `src/session_replay.py` — given a session file and an `LLMEngine`,
   replays every event through `generate_answer_stream` (or
   `generate_vision_answer_stream`) and emits a diff against the original
   answer.
3. Settings → new "Sessions" tab: list recorded sessions, "Replay" button,
   side-by-side diff viewer.
4. Prompts tab gains "Try on session…" button that pipes through #2 with a
   user-edited prompt before saving it.

Estimated 4–6 commits, no new runtime dependencies.

## Out of scope

- UI for editing recorded sessions (delete is fine, edit is not).
- Server-side storage / sharing of sessions.
- Anything that requires the user to be online during replay (replay uses
  the live providers but must work without the original mic input).
